# 3D Print Pipeline — 前端重构设计

## Context

当前前端是 **3689 行**的单文件 `web/templates/index.html`，所有 CSS、JS、i18n 全部内联在一个文件中。随着工作流编辑器、运行器、节点详情等功能不断增加，这个文件已经难以维护。需要在不改变后端 API 和 hash 路由的前提下，将前端重构为模块化架构。

## 设计目标

1. **模块化** — 拆分为独立 CSS/JS/locale 文件
2. **正式 i18n** — locale JSON 文件按需加载，Language 切换不丢状态
3. **UI 升级** — 保留暗色主题，增加微交互、过渡动画、响应式
4. **零破坏** — 所有 `#/` 路由、`/api/*` 端点保持不变
5. **零构建** — ES modules 原生加载，不引入 webpack/vite

## 一、后端改动 (server.py)

最小化改动 —— 只加 3 行：

```python
from fastapi.staticfiles import StaticFiles

STATIC_DIR = os.path.join(os.path.dirname(__file__), "static")
app.mount("/static", StaticFiles(directory=STATIC_DIR), name="static")

@app.get("/")
async def index(request: Request):
    # 根据 Accept-Language 设置 <html lang="...">
    al = request.headers.get("accept-language", "zh")
    lang = "zh" if al.startswith("zh") else "en"
    index_path = os.path.join(STATIC_DIR, "index.html")
    with open(index_path, "r", encoding="utf-8") as f:
        html = f.read()
    return HTMLResponse(html.replace('<html lang="zh">', f'<html lang="{lang}">'))
```

`templates/index.html` 改为重定向页，防止旧书签 404。

## 二、i18n 改造

### 现状问题
- 所有翻译硬编码在 JS 对象中（720行），与业务逻辑混在一起
- 存在大量内联三元表达式 `lang==='zh'?'加载中...':'Loading...'` 未走 i18n
- 切换语言后必须 `route()` 全页重渲染

### 方案：JSON locale + 加载器

```
locales/zh.json  ─┐
                  ├── i18n.js ── t("dash.recent") → "最近任务"
locales/en.json  ─┘
```

**i18n.js 核心 API：**
- `initI18n()` — 首次加载，从 `localStorage` 恢复语言偏好
- `t(key, fallback?)` — 点号路径查找，fallback: 当前语言 → 中文 → key 本身
- `setLang(l)` — 切换语言，加载新 locale，重渲染

**locale JSON 结构（示例片段）：**
```json
{
  "app": { "title": "3D 打印流水线" },
  "nav": { "dashboard": "工作台", "newTask": "新建任务", ... },
  "dash": { "title": "工作台", "recent": "最近任务", "empty": "还没有任务..." },
  "badge": { "queued": "排队", "running": "运行中", ... },
  "detail": { "title": "任务详情", "cancel": "取消任务", ... },
  "wf": { "runner": { "title": "工作流运行", "progress": "执行进度", ... } }
}
```

**落地规则：** 所有用户可见字符串必须走 `t()`。现有代码中 `lang === 'zh' ? '...' : '...'` 的三元表达式全部替换为对应的 locale key。

## 三、JS 模块拆分

使用 `<script type="module">` 入口，所有 JS 文件通过 `import`/`export` 组织：

```
app.js ──→ i18n.js    (语言加载)
       ──→ router.js  (hash 路由表)
              ──→ pages/dashboard.js   (export renderDashboard)
              ──→ pages/new-task.js    (export renderNewTask)
              ──→ pages/task-detail.js (export renderTaskDetail)
              ──→ ...
       ──→ api.js     (api / apiStream)
       ──→ utils.js   (escHtml / toast / formatTime / formatBytes / ctxMenu)
```

每个页面模块 export 一个 `render(container)` 函数。路由表：

```js
const routes = {
  '#/dashboard': () => import('./pages/dashboard.js'),
  '#/new':       () => import('./pages/new-task.js'),
  // ...
};
```

使用动态 `import()` 实现按需加载 —— 用户首次访问某页面时才加载对应 JS。

| 文件 | 行数估算 | 内容 |
|---|---|---|
| `main.css` | ~80行 | 设计令牌 `:root`、reset、body 布局、sidebar、响应式断点 |

| `pages.css` | ~60行 | 页面特有布局（stats 统计卡、type-grid、preview-grid 等） |

### UI 风格升级点

- **间距系统** — 新增 `--space-xs/sm/md/lg/xl` 变量统一间距
- **阴影层级** — `--shadow-sm/md/lg` 三层阴影
- **过渡动画** — 卡片 hover 上浮 `translateY(-2px)`，按钮按下缩放，toast 滑入滑出
- **侧边栏** — 当前页高亮从左边框改为圆角 pill 背景
- **响应式** — `<768px` 侧边栏折叠为图标模式，`<480px` 顶部横排
- **Toast stacking** — 多条 toast 纵向排列而非互相覆盖
